# Правила проекта FreestyleParser

## Языки: всё в двух версиях (RU + EN)

Приложение локализовано (ru/en). Всё, что видит пользователь, ведётся
**одновременно на двух языках**.

### Строки в коде

- Пользовательский текст пишется через `i18n.tr("Русский текст")` —
  gettext-стиль: **сам русский текст является ключом**.
- f-строки с пользовательским текстом → `i18n.tr("Шаблон {name}", name=x)`,
  плейсхолдеры именованные, аргументы kwargs.
- НЕ оборачивать: комментарии, docstrings, `print()` в консоль, `logging`
  (кроме `self.log` — он виден в GUI), внутренние идентификаторы
  (имена файлов/атлетов).
- Строки-значения, сравниваемые в коде (например фильтры `Все` /
  `Неизвестно` / `На подтверждение`), оборачивать `i18n.tr()` **с обеих
  сторон** (set и get) одинаково.
- Файлы с UI-строками: `app.py`, `Components.py`, `utils.py`,
  `splitter.py`, `attempts_v2.py`. Для перерисовки UI при смене языка в
  рантайме — `ui_tr.py` (не вызывать `tr()` до `ui_tr.install()`).

### Файлы переводов

- `locales/en.json` — **новый ключ = сразу добавить перевод** в том же
  коммите. Плейсхолдеры `{name}` и форматы `{n:.1f}` копировать точно.
- `locales/ru.json` не заполняется (fallback: ключ = русский исходник).
- Существующие ключи не переименовывать и не переводить иначе — это
  ломает связку с кодом.
- Проверка перед коммитом: `python3 tools/check_locales.py` (и pre-commit
  hook, и шаг Check locales в CI) — ловит отсутствие перевода, мёртвые
  ключи, несовпадение плейсхолдеров.

### Документация

- `README.md` — секции на русском; при значимых изменениях для
  пользователей добавлять английскую версию (подраздел или `README.en.md`).
- Сообщения коммитов — на русском (исторический стиль репо), заголовок
  может дублироваться по-английски при необходимости.

### Выпуск релиза

Просьба «выпустить релиз» (тег + сборка) включает **обязательную
прозрачность изменений** для тех, кто скачивает релиз со страницы
Releases:

1. Тег `vX.Y.Z` (по последнему тегу +1) → push → CI собирает exe/binary
   и создаёт черновик релиза.
2. Сразу после сборки заполнить релиз (`gh release edit vX.Y.Z`):
   - **Заголовок**: `vX.Y.Z — <короткая суть>`, как `v1.3.7 — Кнопка
     справки в exe`.
   - **Body — release notes на русском**: что нового/изменено/исправлено
     с точки зрения пользователя (не список коммитов); для новых фич —
     1-2 строки «как этим пользоваться». Если значимо для пользователей —
     дублировать короткую английскую версию.
3. Нотисы пишутся для скачивающего, а не для разработчика: без
   внутреннего жаргона, с ссылками на README/разделы справки, если нужно.

### Добавление нового языка

1. Скопировать `locales/en.json` → `locales/<код>.json`, перевести значения.
2. Ключ `lang.name` — название языка на самом языке (для списка выбора).
3. Код появится в переключателе `🌐` в правом верхнем углу автоматически.
